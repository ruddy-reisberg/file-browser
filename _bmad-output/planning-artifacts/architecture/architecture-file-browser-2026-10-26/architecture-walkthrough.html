file-browser: architecture walkthrough

For the course grader. How the rules in CLAUDE.md became eight architecture decisions, what the review changed, and what the author decided. The contract itself is ARCHITECTURE-SPINE.md in this folder.

1. The process

  1. Brief → PRDProduct brief, then a PRD with FR-1 to FR-11, including the audio/video mini-player (FR-9 to FR-11) from prompts/level-4/ears.md.
  2. Architecture spine (fast path)Drafted from the PRD and a read of the real code. Each decision is logged in .memlog.md before it reaches the spine.

4. What the reviewers found

Corrected: the docs misdescribed the code

The code shipped a webkitdirectory fallback while the PRD and CLAUDE.md said there was none. The spine overclaimed lint enforcement: only the React-import ban is mechanical, the rest is review and tests.

Tightened: gaps two independent builders could fall into

Three separate "kind" vocabularies would each grow audio and video differently. The 3D Leaf unmounts 260 ms after a close request, so audio would keep playing, and its focus trap skips audio and video controls. A second selection owner (openNode in the scene) can disagree with App.selected.

Open: unverified

Keyboard operability of native media controls is an assumption until checked by hand in current Chrome and Edge. Dependency pins are one or two majors behind npm latest and were kept as adopted.

5. Decisions made by the author

  • Remove the webkitdirectory fallback. Done in code, tests and docs.
  • Lift the filter to App. Done: the 3D sign and a new list-view input share one query.
  • Revoke the media URL on selection change or unmount, not when playback ends, so replay works. Recorded in the PRD (FR-10).
  • Write this walkthrough.

6. Not built yet

The mini-player (MediaPlayer, file-kind.ts) is specified by AD-5 to AD-7 but not implemented. Deferred by design: a 3D size cap, previews for other file types, mechanical lint for the no-network and no-write rules, CI and hosting.
