# file-browser release check

Read-only verification that ends in a **GO / NO-GO** verdict. Do not modify source files, and do not commit, tag, push, publish or deploy: those need explicit user approval (offer them after a GO). `dist/` is regenerated by the build, which is the only write allowed.

Run the gates in order; keep going after a failure so the report is complete, but any failed gate = NO-GO.

## Gate 1: repository state

- `git status --short`: no uncommitted or untracked source changes (note anything that is deliberately excluded). `dist/` and `*.tsbuildinfo` must be git-ignored.
- `git branch --show-current` and `git log main..HEAD --oneline`: state the branch and what is being released. Warn if not on the expected release branch.
- `package.json` `version` vs `git tag --list` : flag a version that was already tagged, or has not been bumped since the last tag when the user expects a bump.

## Gate 2: code health

- `npm run check` (typecheck + lint + tests). Quote failures verbatim. Count `.skip`, `.only`, `eslint-disable`, `@ts-ignore`, `any` additions since the last tag or `main` (`git diff <base> -- src`): each is a finding unless justified in a comment.
- `npm audit --omit=dev` : report high/critical advisories in runtime dependencies (informational for low/moderate). Note `@modelcontextprotocol/sdk` and `zod` are in `dependencies` although only `mcp/server.mjs` uses them: flag if they end up in the browser bundle (see Gate 4).

## Gate 3: production build

- `npm run build` (`tsc -b` + `vite build`). Must exit 0. Record chunk list and sizes from the output; flag any Vite chunk-size warning.
- Optionally `npm run preview` and open it (`/run`) to smoke test: pick a folder, tree renders, image/PDF/media preview, 3D view loads, fallback to list works when WebGL is unavailable.

## Gate 4: inspect `dist/` against the project's Forbidden list

Grep the built `dist/` (assets and `index.html`):

1. **External URLs/CDN**: `https?://` hits must be only inert strings (XML/SVG namespaces such as `w3.org`, `reactjs.org` error-doc links inside React, three.js license/doc comments). Any font/texture/worker/script/stylesheet loaded from a remote host = blocking. `index.html` must reference only local `/assets/...`.
2. **Network and persistence in app code**: `sendBeacon`, `localStorage`, `sessionStorage`, `indexedDB`, `document.cookie`, `createWritable`, `removeEntry`, `showSaveFilePicker`. Library code may contain some of these strings (React scheduler, three, pdf.js); judge each hit by whether app code can reach it, and mark library-only hits as accepted with a note.
3. **Picker mode**: the bundle still calls `showDirectoryPicker` with `mode:"read"` (grep `showDirectoryPicker`).
4. **pdf.js worker**: a `pdf.worker*.js` (or equivalent) emitted under `dist/assets/` and referenced by a local URL, no remote worker.
5. **Lazy 3D scene**: three/R3F/drei live in their own chunk(s), not in the entry chunk. Check the entry chunk does not contain three.js markers (e.g. `WebGLRenderer`), and that a separate chunk does. If the entry contains it, the `React.lazy` split regressed = blocking.
6. **Server-only deps**: no `@modelcontextprotocol`, `zod` or `mcp/server` code in `dist/`.
7. **Source maps / secrets**: no `.map` files unless intended; no `.env` content, absolute local paths (`C:\\Users`), or tokens (`grep -ri "C:\\\\Users\|api[_-]\?key\|secret\|token" dist`).

## Gate 5: rules spot-check

Run a quick pass of the `audit-rules` skill sections 2 (Forbidden greps) on `src/`. A full audit is not required here, but any Forbidden hit is NO-GO.

## Report

```
Release check: <package version> on <branch> @ <short sha>
Gate 1 repo state      OK / FAIL  (details)
Gate 2 code health     OK / FAIL  (check result, audit summary)
Gate 3 build           OK / FAIL  (chunks and sizes)
Gate 4 dist inspection OK / FAIL  (per item 1-7)
Gate 5 rules spot-check OK / FAIL
Verdict: GO / NO-GO
```

For each failure: clickable `file:line` (or `dist/assets/<file>` with the matched snippet), severity (blocking / important / minor), one-sentence problem, short fix. Mark unverified items "to confirm" and say what could not be run. After a GO, list the next steps (bump version, tag, deploy) as suggestions and wait for the user's approval before doing any of them.
